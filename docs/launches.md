# Launches, jobs and audits

Every contract imd/acc runs was built, audited and deployed by the [IMD swarm](https://imd.fun) from this repository, in paid jobs. This page lists each job with its launch, the contracts it deployed, the code it delivered and what its audit found, so anyone can check the record. The blow-by-blow is in [history.md](history.md); the job texts are in [`jobs/`](../jobs/).

**How to check a job yourself** (all public, no key): `https://api.imd.fun/jobs/<job id>` (state, steps, launch), `https://api.imd.fun/jobs/<job id>/submissions` (each step's summary and the judge's findings), `https://api.imd.fun/launches/<launch id>` (addresses, admission checks). The delivered code is in a public GitHub repository under `identity-md-launches`, one per launch. Every launch passes seven admission checks before it deploys: provenance, findings, independent review, reproducible bytecode, manifest, protected invariants, economics.

## What the audits found

Each launch runs an import audit, an adapt step, a tests step, four specialist audits (math, permissions, economics, control flow) and a judge who reproduces, merges and ranks the findings; a critical or high finding stops the launch. Nothing critical or high was ever found. What was found, and what happened to it:

| Launch | Findings | Outcome |
|---|---|---|
| #1129 (test run 1) | None kept by the judge. An independent check here: the bytecode reproduces exactly with forge 1.8.3; Slither's 7 results all expected. | Deployed as written. |
| #1294 (test run 2) | **Medium:** a project's beneficiary could change wallets ahead of a challenge and collect the bond. **Lows:** an answer's request id never consumed; an unbounded cooldown; a challenge restated the application rate; a 1-wei credit renews a trader's one-block hold. | Fixed by IMD before deploying: `challengeForBeneficiary` pins the wallet, each answer is consumed once, the cooldown is capped at 365 days, a challenge judges the current rate; the Stacker's constructor makes no external call and the first credit checks the vault. The hold is a property of the existing vault, documented. |
| Job 8 and #1371 (test run 3) | **Medium (job 8):** after the pin above, a beneficiary could still refuse every challenge by moving the wallet back and forth ahead of each one. **Lows (#1371):** a beneficiary's own challenge takes the slot for the fee alone; a bond the token refuses to pay could hold a question open for good. | IMD fixed the medium: at most one handoff per day. The self-challenge is a documented limit (it still puts the project before the panel). The owed-bond low was fixed in `main` before test run 4. |
| #1378 (test run 4) | **Low:** the self-challenge above. **Info:** token edge cases unreachable with IMD or the test IMD. | Documented. |
| #1409 (mainnet Stacker) | **Low:** `credit` accepted the Stacker, the vault or the IMD token as the trader, stranding the shares. **Medium:** the integration rule's "fall back to `sender`" names the router in a Uniswap v4 hook, so a frontend swap would credit the router. **Low:** a hook that caps the call near the new-trader gas fails the first-ever credit. | IMD added `InvalidTrader` to the Stacker before deploying (the live code). The trader rule was rewritten (hookData, else the router's `msgSender()`, else `sender` only without code), and became the registry's version 3. The README's gas budget was set to 350k with a 410k check. |
| #1428 (test run 5) | **Low:** the owner rule locks out a project whose reported owner can never send a transaction (a burn address). **Info:** an `owner()` costing over 30,000 gas reads as no owner. | Design choice, documented. |
| #1463 (test run 6) | **Lows:** the owner gate fails open behind seven or more proxy hops; the self-challenge. **Info:** a `uint256` or `bool` `owner()` locks a project out; signer, Intake and action fixed for life; delisting is not retroactive. | Documented trade-offs of the no-owner design. |
| #1495 (mainnet ProjectRegistry) | **Low:** a project could name the registry itself as beneficiary; a defended bond paid there would be stranded (a token self-transfer records nothing in `bondOwed`). **Low:** a stranger can hold an ownerless project's application slot for the fee per round. **Info:** the accepted self-challenge limit (recorded as the brief asked); signer, Intake and panel constants fixed for life; the Intake writer pairs answers to questions. | IMD added one guard before deploying: `applyListing` and `setBeneficiary` refuse the registry's own address (`InvalidBeneficiary`); the deployed code is `main`'s plus those four lines, since brought into `main`. The ownerless-slot point is the documented limit for projects without an `owner()` (owned projects are protected by the owner rule). The rest documented. |
| #1529 (mainnet StackReceiver) | **Medium:** the zero-share fallback could not work: a `revert` inside the `try` success block is not caught, so a deposit minting zero shares would have reverted the whole delivery and locked that message's IMD (not reachable with the live vault, but a broken guarantee). **Info:** `lzCompose` is payable and ETH sent with it was stuck. **Lows, in the RemoteStacker (not deployed here):** sub-step dust was tipped again on later flushes; new cashback merged into a balance past the 12-hour cap paid the full tip at once; a fork test's gas-margin check was inverted. **Info:** the receiver deposits for any listed address (a hostile sender can strand only its own IMD); IMD's OFT owner is not renounced, so the bridge's settings are a trust assumption. | IMD fixed the medium and the info before deploying: the receiver previews the deposit first (`previewDeposit`) and pays plain IMD on a zero preview, and refuses ETH sent with a compose (`UnexpectedValue`); the deployed code is the pinned commit's plus that. The three lows were fixed in `main` the same day (history 50). The two infos documented. |
| #1537 (Robinhood Chain RemoteStacker) | **Medium (tests):** the receiver's launch test brought into `main` from #1529 pinned the manifest to a StackReceiver, so two tests failed on the Robinhood branch. **Lows:** Ethereum's IMD token and endpoint were not refused as traders (only Robinhood's IMD was); the weighted waiting clock rounded down to the second, so fresh cashback could be tipped at once. **Low (judge, after the fix):** rounding the clock up a whole second per credit compounds, so frequent or 1-wei credits can hold one trader's flush tip at zero (no funds lost; the trader keeps at least 98% and can flush themselves). **Info:** a NatSpec line names `Queued` with three fields (it has four); the brief's test count was stale; IMD's bridge owner controls the only exit. | IMD fixed the medium and the two first lows before deploying: the test skips on other manifests; `credit` and `setEthereumRecipient` refuse Ethereum's IMD and endpoint; the clock uses `Math.ceilDiv`. The deployed code is the pinned commit's plus that. The judge's rounding low is documented; an exact weighted-sum clock is the fix for later chains. The infos documented. |
